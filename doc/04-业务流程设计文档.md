# LobeChatService 业务流程设计文档

## 1. 业务流程概述

LobeChatService 的核心业务流程包括用户认证、会话管理、消息处理、AI模型调用、Token管理等。本文档详细描述了各个业务流程的执行逻辑和交互关系。

## 2. 用户认证与权限验证流程

### 2.1 用户登录认证流程

```plantuml
@startuml
actor 用户 as User
participant "前端应用" as Frontend
participant "认证服务" as AuthService
participant "用户数据库" as UserDB
participant "权限服务" as PermissionService

User -> Frontend: 输入用户名密码
Frontend -> AuthService: 发送认证请求
AuthService -> UserDB: 验证用户信息
UserDB -> AuthService: 返回用户数据

alt 认证成功
    AuthService -> PermissionService: 查询用户权限
    PermissionService -> AuthService: 返回权限信息
    AuthService -> Frontend: 返回认证token和权限
    Frontend -> User: 登录成功
else 认证失败
    AuthService -> Frontend: 返回认证失败
    Frontend -> User: 显示错误信息
end

@enduml
```

### 2.2 权限验证流程

```plantuml
@startuml
participant "API请求" as Request
participant "权限验证器" as AuthValidator
participant "用户组角色表" as UserRoleDB
participant "业务服务" as BusinessService

Request -> AuthValidator: 携带用户标识的API请求
AuthValidator -> UserRoleDB: 查询用户权限信息
UserRoleDB -> AuthValidator: 返回group_id和role_id

alt 基础模型权限验证
    AuthValidator -> AuthValidator: 检查 group contains "1" OR role >= 1
    alt 权限充足
        AuthValidator -> BusinessService: 允许访问
    else 权限不足
        AuthValidator -> Request: 返回403权限不足
    end
else 高级模型权限验证
    AuthValidator -> AuthValidator: 检查 group contains "2" OR role >= 2
    alt 权限充足
        AuthValidator -> BusinessService: 允许访问
    else 权限不足
        AuthValidator -> Request: 返回403权限不足
    end
end

@enduml
```

## 3. 会话管理流程


### 3.2 会话恢复流程

```plantuml
@startuml
actor 用户 as User

participant "会话服务" as SessionService
participant "缓存服务" as Cache

User -> Frontend: 选择历史会话

    SessionService -> Cache: 更新缓存

SessionService -> MessageService: 获取历史消息
MessageService -> SessionService: 返回消息列表
SessionService -> Frontend: 返回完整会话数据
Frontend -> User: 显示会话历史

@enduml
```

## 4. 消息处理与AI调用流程

### 4.1 消息发送与AI响应流程

```plantuml
@startuml
actor 用户 as User
participant "前端界面" as Frontend
participant "消息服务" as MessageService
participant "权限验证" as AuthService
participant "AI路由" as AIRouter
participant "AI服务商" as AIProvider
participant "Token服务" as TokenService
participant "消息数据库" as MessageDB

User -> Frontend: 发送消息
Frontend -> MessageService: 提交用户消息
MessageService -> AuthService: 验证用户权限

alt 权限验证通过
    AuthService -> TokenService: 检查Token余额
    
    alt Token充足
        TokenService -> MessageService: 确认可以调用
        MessageService -> MessageDB: 保存用户消息
        MessageService -> AIRouter: 转发到AI服务
        AIRouter -> AIProvider: 调用具体AI模型
        
        AIProvider -> AIRouter: 流式返回AI响应
        AIRouter -> MessageService: 转发AI响应
        MessageService -> Frontend: 实时推送响应
        Frontend -> User: 显示AI回复
        
        MessageService -> MessageDB: 保存AI响应
        MessageService -> TokenService: 记录Token使用
        
    else Token不足
        TokenService -> MessageService: Token余额不足
        MessageService -> Frontend: 返回余额不足提示
        Frontend -> User: 显示充值提示
    end
    
else 权限验证失败
    AuthService -> MessageService: 权限不足
    MessageService -> Frontend: 返回权限错误
    Frontend -> User: 显示权限不足信息
end

@enduml
```

### 4.2 AI模型选择与负载均衡流程

```plantuml
@startuml
participant "消息服务" as MessageService
participant "AI路由器" as AIRouter
participant "负载均衡" as LoadBalancer
participant "OpenAI服务" as OpenAI
participant "DeepSeek服务" as DeepSeek
participant "Google服务" as Google
participant "服务监控" as Monitor

MessageService -> AIRouter: AI请求 (model: gpt-4)
AIRouter -> AIRouter: 解析模型类型
AIRouter -> LoadBalancer: 选择服务实例

alt OpenAI模型
    LoadBalancer -> Monitor: 检查OpenAI服务状态
    Monitor -> LoadBalancer: 返回可用实例
    LoadBalancer -> OpenAI: 转发请求
    OpenAI -> LoadBalancer: 返回响应
    
else DeepSeek模型
    LoadBalancer -> Monitor: 检查DeepSeek服务状态
    Monitor -> LoadBalancer: 返回可用实例
    LoadBalancer -> DeepSeek: 转发请求
    DeepSeek -> LoadBalancer: 返回响应
    
else Google模型
    LoadBalancer -> Monitor: 检查Google服务状态
    Monitor -> LoadBalancer: 返回可用实例
    LoadBalancer -> Google: 转发请求
    Google -> LoadBalancer: 返回响应
end

LoadBalancer -> AIRouter: 返回AI响应
AIRouter -> MessageService: 转发响应

@enduml
```

## 5. Token管理流程

### 5.1 Token申请流程

```plantuml
@startuml
actor 用户 as User
participant "前端界面" as Frontend
participant "Token申请服务" as ApplicationService
participant "申请数据库" as ApplicationDB
participant "审批服务" as ApprovalService
participant "管理员" as Admin
participant "Token余额服务" as BalanceService

User -> Frontend: 填写Token申请
Frontend -> ApplicationService: 提交申请
ApplicationService -> ApplicationDB: 保存申请记录

ApplicationService -> ApprovalService: 触发审批流程
ApprovalService -> Admin: 发送审批通知

Admin -> ApprovalService: 审批决定

alt 审批通过
    ApprovalService -> BalanceService: 增加用户Token
    BalanceService -> ApplicationService: 确认余额更新
    ApplicationService -> ApplicationDB: 更新申请状态
    ApplicationService -> Frontend: 通知申请通过
    Frontend -> User: 显示审批通过
    
else 审批拒绝
    ApprovalService -> ApplicationDB: 更新申请状态为拒绝
    ApplicationService -> Frontend: 通知申请被拒绝
    Frontend -> User: 显示拒绝原因
end

@enduml
```

### 5.2 Token使用与扣减流程

```plantuml
@startuml
participant "AI调用服务" as AIService
participant "Token服务" as TokenService
participant "余额数据库" as BalanceDB
participant "使用记录数据库" as UsageDB
participant "计费服务" as BillingService

AIService -> TokenService: 请求Token验证
TokenService -> BalanceDB: 查询用户余额

alt 余额充足
    BalanceDB -> TokenService: 返回当前余额
    TokenService -> AIService: 确认可以调用
    
    AIService -> AIService: 执行AI调用
    AIService -> BillingService: 计算实际使用量
    BillingService -> AIService: 返回使用Token数量
    
    AIService -> TokenService: 扣减Token
    TokenService -> BalanceDB: 更新余额
    TokenService -> UsageDB: 记录使用记录
    
    TokenService -> AIService: 确认扣减完成
    
else 余额不足
    BalanceDB -> TokenService: 余额不足
    TokenService -> AIService: 拒绝调用
    AIService -> AIService: 返回余额不足错误
end

@enduml
```

## 8. 安全模块流程

### 8.1 消息内容过滤流程

```plantuml
@startuml
participant "用户消息" as UserMessage
participant "安全过滤器" as SecurityFilter
participant "内容检测" as ContentDetector
participant "掩码处理" as MaskProcessor
participant "输出消息" as OutputMessage

UserMessage -> SecurityFilter: 原始消息内容
SecurityFilter -> ContentDetector: 检测敏感内容

alt 包含敏感内容
    ContentDetector -> MaskProcessor: 标记敏感内容
    MaskProcessor -> MaskProcessor: 执行掩码处理
    MaskProcessor -> SecurityFilter: 返回处理后内容
    SecurityFilter -> OutputMessage: 输出安全内容
    
else 内容安全
    ContentDetector -> SecurityFilter: 确认内容安全
    SecurityFilter -> OutputMessage: 直接输出原内容
end

@enduml
```

## 10. 异常处理流程

### 10.1 系统异常处理流程

```plantuml
@startuml
participant "业务操作" as BusinessOp
participant "异常捕获" as ExceptionHandler
participant "日志服务" as LogService
participant "通知服务" as NotificationService
participant "响应构建" as ResponseBuilder
participant "客户端" as Client

BusinessOp -> ExceptionHandler: 抛出异常
ExceptionHandler -> LogService: 记录错误日志
ExceptionHandler -> ExceptionHandler: 分析异常类型

alt 业务异常
    ExceptionHandler -> ResponseBuilder: 构建业务错误响应
    ResponseBuilder -> Client: 返回友好错误信息
    
else 系统异常
    ExceptionHandler -> NotificationService: 发送告警通知
    ExceptionHandler -> ResponseBuilder: 构建系统错误响应
    ResponseBuilder -> Client: 返回通用错误信息
    
else 未知异常
    ExceptionHandler -> LogService: 记录详细错误
    ExceptionHandler -> NotificationService: 发送紧急告警
    ExceptionHandler -> ResponseBuilder: 构建默认错误响应
    ResponseBuilder -> Client: 返回默认错误信息
end

@enduml
```
